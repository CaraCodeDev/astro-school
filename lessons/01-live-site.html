Astro School · Lesson 1

From your terminal to a live site

By the end of this hour a website you can edit will be on the internet at a real address, and you'll have changed it once, from your Mac, on purpose.

What you'll be able to say at the end

"The website is a folder on my Mac. GitHub holds the master copy. Pushing is what publishes it."

That one sentence is the whole lesson. Everything below is in service of it. If it's true for you by the end, you've got it, even if you couldn't repeat a single command from memory.

Before you start

  • Lesson 0 is done. Ghostty opens with a coloured prompt.
  • You're logged in to GitHub and Cloudflare in your browser.
  • Zed is in your Applications folder.

1. Get your own copy of the site

Open Ghostty. The prompt shows a folder name, probably ~, which is your home folder. Move into the repo folder from lesson 0:

cd repo

Watch the prompt change to ~/repo. That's the terminal telling you where you're standing. Every command you type runs in that folder.

Now make your own copy of the starter site:

gh repo create delightful-deli --template CaraCodeDev/delightful-deli --public --clone

This does three things in one go. It creates a new repo called delightful-deli in your GitHub account. It fills it with a copy of the starter. Then it clones that repo onto your Mac, into a folder called delightful-deli, right where you're standing.

Step into it:

cd delightful-deli

The prompt now shows the folder and a git branch called main. When you see a branch name in the prompt, you're inside a repo. When you don't, you're not.

The starter is a two-page site for a deli on Cashel Street. It's not real. It exists so you have something with a header, footer, a menu, a card grid, and a second page to poke at. You'll build your own from scratch in lesson 3.

2. Run it on your Mac

The site needs its libraries before it can run. Fetch them:

pnpm install

Twenty seconds of scrolling text, then a summary. A folder called node_modules has appeared. It's big, it's not yours, and git ignores it. Every project has one. You never open it.

pnpm and npm, properly this time. Both install libraries. npm comes with node, pnpm is a faster replacement that keeps one copy of each library on your disk instead of one per project. The project tells you which one it expects: a file called pnpm-lock.yaml means pnpm, package-lock.json means npm. Use the wrong one and nothing obviously breaks, which is the trap. You'd get a second lockfile, git would show a file you didn't touch, and the next person to open the project would get subtly different library versions. Every project in this course has a pnpm lockfile. Type pnpm.

Now start it:

pnpm dev

It prints an address, http://localhost:4321. Open that in your browser. There's the deli.

What you're looking at is the site running on your own Mac, served by a small program in that Ghostty window. "localhost" means "this computer". Nobody else can see it. It rebuilds instantly every time you save a file, which is how you'll check work before it goes anywhere.

Leave it running. The terminal is busy now, so it won't take new commands. That's expected. When you eventually want it back, press Ctrl+C and the server stops.

3. Look inside

Open a second Ghostty tab with Cmd+T. It starts in the same folder. Open the project in Zed:

zed .

The dot means "this folder". Zed opens with a file tree on the left. Here's the map, with the Webflow name for each thing:

That's the whole mental model you need. Pages, symbols, a wrapper, styles, assets. Everything else in the tree is plumbing.

4. Put it on the internet

This part happens in the browser. Cloudflare will watch your GitHub repo and rebuild the site every time it changes.

  1. Go to dash.cloudflare.com and open Workers & Pages in the left sidebar.
  2. Click Create, then Import a repository.
  3. Connect your GitHub account when asked. GitHub will ask which repos Cloudflare may see. Pick delightful-deli, or all repos if you'd rather not do this again.
  4. Select delightful-deli from the list.
  5. On the settings screen, check two fields. Build command should be pnpm build. Deploy command should be npx wrangler deploy. Leave the rest alone.
  6. Click Deploy.

A build log scrolls for a minute or so. When it finishes there's a link ending in workers.dev. Open it. That's your site, on the internet, for anyone.

What just happened. Cloudflare cloned your repo the same way you did, ran pnpm install and pnpm build the same way you could, and put the result on its servers. It's the same site, built the same way. The only difference from localhost is who can see it.

Give Rich a key

Two minutes, while you're here. This lets Rich see your dashboard, builds, and logs from his own login, which is how he'll help when something goes sideways.

  1. Click Manage Account in the sidebar, then Members.
  2. Click Invite, enter Rich's email, choose Administrator, and send.

Do the same on GitHub: open your delightful-deli repo, Settings, Collaborators, add Rich. The account is yours. You're handing out a key, not the house.

5. Change it, on purpose

This is the part that matters. You'll change one thing and follow it all the way from your keyboard to the live site.

In Zed, open src/pages/index.astro. Near the top there's a list called counter. Find the cheese scone and change its price from 6 to 7. Save with Cmd+S.

Look at the localhost tab in your browser. The price already says $7. That's the dev server doing its job. Now look at the live workers.dev site. Still $6. Of course it is. You saved a file on your Mac and nothing has left your Mac.

Look at the Ghostty prompt. There's a small marker next to the branch name now. That's the prompt telling you the folder has changes git doesn't know about yet.

In the second Ghostty tab, the one that isn't running the dev server, ask git what changed:

git status

It lists index.astro in red. Modified, not yet recorded. Record it:

git add -A
git commit -m "Cheese scone is now $7"

The first line says "include everything that changed". The second takes a snapshot and labels it. The label is for you and Rich, six months from now, wondering what changed and why. Write it like a text message.

The marker in the prompt is gone. The snapshot exists, but only on your Mac. Send it:

git push

Now go to the Cloudflare tab. Within a few seconds a new build starts on its own. When it finishes, refresh the live site. $7.

Saved

The file on your Mac changed. Localhost shows it. Nothing else does.

Cmd+S
Committed

Git took a labelled snapshot. Still only on your Mac.

git add, git commit
Pushed

The snapshot went to GitHub. Cloudflare saw it and rebuilt the site.

git push

Three states. Webflow's Publish button does all three at once and hides it. Here they're separate, and once you can feel the difference you'll never again wonder why a change "didn't work".

Do it once more on your own. Pick anything: a menu item, a line in the FAQ, the deli's hours. Save, check localhost, add, commit, push, watch the build, refresh. The second time is where it goes from "followed the instructions" to "I know how this works".

Why you typed those git commands yourself

From lesson 2, Claude will do the committing and pushing for you and you'll rarely type them again. So why learn them? Because when Claude says "I've committed and pushed your changes", you now know exactly what that sentence means, what should be true afterwards, and how to check. That's the difference between trusting a tool and directing it.

If something goes wrong

"command not found: pnpm" or "command not found: gh"
Quit Ghostty completely and open it again. The setup from lesson 0 needs a fresh window to take effect.
"Port 4321 is in use"
A dev server is already running in another tab. Find it and press Ctrl+C, or just use the address it printed. Astro picks the next free port on its own.
The browser shows the old site after a push
Check the Cloudflare build finished. Then hard refresh with Cmd+Shift+R. Browsers hold on to old copies.
git push says "rejected" or asks for a password
Run gh auth status. If it says you're not logged in, run gh auth login again and pick the same options as lesson 0.
The Cloudflare build failed
Open the build log, scroll to the first line in red, copy it and the ten lines above, and send them to Rich. Don't retype.
Something else
Copy the last 20 lines from Ghostty and send them. Running any of these commands twice is safe.

Words you'll hear

Clone
Copy a repo from GitHub onto your Mac. Done once per project.
Dev server
The program pnpm dev starts. Serves the site to your browser from your Mac and rebuilds on every save.
localhost
This computer. An address only your machine can reach.
node_modules
The folder of libraries pnpm installs. Big, ignored by git, never edited.
Commit
A labelled snapshot of the project, stored by git on your Mac.
Push
Send commits from your Mac to GitHub.
Build
Turn the source files into the plain HTML, CSS, and images a browser needs. pnpm build does it. Cloudflare runs it for you after every push.
Deploy
Put the built site where the world can reach it. Cloudflare does this after the build.
Branch
A named line of history. You'll only ever see one, called main, for now.
