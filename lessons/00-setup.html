Astro School · Lesson 0

Set up your Mac

One command turns a fresh Mac into a machine that can build and publish websites. This page explains what that command does and why, so nothing that happens on screen is a mystery.

What you'll have at the end

  • A terminal app called Ghostty that looks good and tells you where you are.
  • A code editor called Zed.
  • The tools that run Astro and talk to GitHub, installed and logged in.
  • A GitHub account and a Cloudflare account, ready for lesson 1.

Budget 20 to 30 minutes. Most of that is downloading, and there are only three moments where you need to do anything.

First, two accounts

Make these now if you don't have them. Use the same email for both, it saves confusion later.

GitHub
Where your website's files live. Think of it as the master copy. Every change you make gets sent here, and the hosting reads from here. Free.
Cloudflare
Where the website is actually served from. It watches your GitHub repo and rebuilds the site every time something changes. Also free for what we're doing.

If you're joining an existing team account on either service, you'll get an invite instead. Still make a personal GitHub account, because the invite needs one to attach to.

The command

Press Cmd + Space, type Terminal, press Enter. A plain white or black window opens with a blinking cursor. Paste this in and press Enter.

curl -fsSL https://raw.githubusercontent.com/CaraCodeDev/astro-school/main/setup.sh | bash

What that line means

It's two instructions joined by the vertical bar. The first half, curl, downloads a file from the internet. The address is a file called setup.sh that lives in a public GitHub repo. The second half, bash, runs whatever it was handed as a series of commands. So: download the script, run the script.

You can read the script before you run it. It's plain text, and every step in it is described below. Open it here: setup.sh on GitHub.

A habit worth forming. Piping a download straight into bash is normal in this world, and it's also how people get tricked. Only do it when you know who wrote the script and can read it. This one is ours.

The three moments that need you

  1. A dialog asks to install command line tools. Click Install. It takes a few minutes. When it's done, paste the command again and press Enter. The script picks up where it left off.
  2. It asks for your Mac password. Type it and press Enter. Nothing appears as you type, not even dots. That's normal.
  3. It asks you to log in to GitHub. Use the arrow keys and Enter to choose GitHub.com, then HTTPS, then Yes, then Login with a web browser. It shows you a code, opens your browser, and you paste the code in.

Everything else runs on its own. When you see Done, quit Terminal. You won't use it again.

What the script does, step by step

Six steps. Each one prints its number as it starts, so you can match what's on screen to what's here.

1

Apple command line tools

Checks whether Apple's developer tools are installed. If not, it triggers the install dialog and stops, so you can click Install and run the command again.

Why. This is the one thing everything else depends on. It includes git, the program that tracks changes to files, and the compilers Homebrew needs. It's not the full Xcode app, just the pieces that work in a terminal. About 2 GB.

2

Homebrew

Installs Homebrew if it isn't there. This is the step that asks for your password.

Why. Homebrew is an app store for the terminal. Instead of hunting down installers from a dozen websites, you tell Homebrew what you want and it fetches, installs, and later updates it. Nearly every tool on this page arrives through it.

3

Get the setup files

Makes a folder at ~/repo and copies the astro-school repo into it. The ~ means your home folder, so this is Users/yourname/repo/astro-school.

Why. The script needs the list of tools and the config files, and those live in the same repo. This is also your first git clone, which is the thing you'll do in lesson 1 to get a website onto your machine. And ~/repo becomes the folder where all your projects go, so you always know where to look.

4

Install tools and apps

Reads a file called Brewfile, which is a shopping list, and hands it to Homebrew. This is the slow step.

Why each thing is on the list.

ToolWhat it's for
gitTracks every change to every file in a project. Lets you see what changed, undo, and send changes to GitHub.
ghGitHub's own command line app. Its main job here is logging you in, which means you never set up keys or tokens by hand.
nodeRuns JavaScript outside a browser. Astro is written in JavaScript, so this is what runs it.
pnpmInstalls a project's dependencies, the libraries it's built on. You'll type pnpm install once per project and pnpm dev every time you work on it.
starshipThe prompt. The coloured bar that shows which folder you're in and which git branch, and warns you when there are unsaved changes.
zsh-autosuggestionsGrey ghost text that guesses the command from your history. Press Tab to accept it.
zsh-syntax-highlightingColours what you type. Green means it's a real command, red means a typo. You find out before pressing Enter.
ezaA nicer ls, the command that lists files. Adds icons and colour.
zoxideMakes cd, the command for moving between folders, remember where you've been. cd astro jumps to the astro-school folder from anywhere.
microA text editor that runs inside the terminal and behaves like a normal app. Cmd-style shortcuts, a menu, no secret modes. Some tools open an editor on you, and this makes sure it's a friendly one.
GhosttyThe terminal app you'll actually use. Faster and better looking than the built-in one.
ZedThe code editor. Where you open a project to read files and make small edits.
JetBrains Mono Nerd FontA monospace font with icons baked in. The prompt needs it for the arrows and symbols. Without it you'd see boxes.

npm or pnpm? You'll see both names online. They do the same job, installing the libraries a project needs. npm comes with node and is the one most tutorials use. pnpm is a faster replacement that stores each library once on your disk instead of once per project, and it's what our projects use. The rule: if a project has a file called pnpm-lock.yaml, use pnpm. If it has package-lock.json, use npm. Every project we touch together will be the first kind, so for now just type pnpm and forget npm exists.

5

Terminal config

Copies three small text files into place, then asks for your name and email if git doesn't know them yet.

Why. Terminal apps are configured by text files in your home folder, usually starting with a dot so they're hidden. People call them dotfiles. The three here are:

~/.zshrc
Runs every time a terminal window opens. Turns on the suggestions and highlighting, sets up the nicer ls and cd, and starts the prompt.
~/.config/starship.toml
What the prompt shows and what colours it uses.
~/.config/ghostty/config
Font, theme, and window look for Ghostty.

If any of these already existed, the old one is saved with .backup and a date on the end. Nothing is lost.

The name and email. Git stamps every change with who made it. The email should match your GitHub account so GitHub can connect the two.

6

Log in to GitHub

Runs gh auth login, which walks you through the browser login described above.

Why. Sending changes to GitHub needs proof it's you. The old way was generating keys and pasting them into settings pages. gh does the browser dance once and remembers, so from then on git push just works.

After it says Done

Quit Terminal. Open Ghostty from Applications. You should see a coloured bar with a folder name in it and a ❯ underneath. That's the prompt. It's waiting for you.

Type ls and press Enter. You'll get a list of the folders in your home directory, with icons. Type cd repo and press Enter, and watch the folder name in the prompt change. That's all a terminal is: you're standing in a folder, and you type what you want done.

You're done. Bring this to lesson 1 and we'll put a website on the internet from that window.

If something goes wrong

Something red appeared, or it stopped without saying Done. Don't retype anything and don't try to fix it. Select the last 20 or so lines in the terminal, copy them, and send them over. The words in the error are the whole point, so copy, don't describe.

Running the command a second time is always safe. It checks what's already done and skips it.

Words you'll hear

Terminal
A window where you type commands instead of clicking. Ghostty is one. So is the built-in Terminal app.
Shell
The program inside the terminal that reads what you type. On a Mac it's called zsh. The terminal is the window, the shell is what's running in it.
Prompt
The bit the shell prints to say it's ready. Ours shows the folder and git branch.
Repo
Short for repository. A folder that git is tracking. A website is a repo. This setup is a repo.
Clone
Copying a repo from GitHub onto your machine.
Push
Sending your changes from your machine up to GitHub.
Dotfile
A hidden config file in your home folder, named with a leading dot.
~
Your home folder. ~/repo is the repo folder inside it.
